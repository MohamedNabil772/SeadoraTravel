## 1. What this is

Seadora Travel is a **luxury Egyptian travel/yacht booking platform** (Hurghada, Red Sea) built as a **.NET 9 microservices** backend behind a **YARP API gateway**, with **two Vue 3 + Vite SPAs** (public website + admin dashboard). Persistence is **PostgreSQL, database-per-service**. Everything is orchestrated with Docker Compose.

## 2. Component / topology overview

### Gateway routing (`src\ApiGateway\appsettings.json`)
- `/api/content/{**catch-all}` → `content-service` (strips `/api/content`) — **public, no admin policy**
- `/api/booking/{**catch-all}` → `booking-service` (strips `/api/booking`) — **public, no admin policy**
- `/api/auth/api/{**catch-all}` → `identity-service` (strips `/api/auth`)
- `/api/concierge/{**catch-all}` → `content-service`
- `/api/files/{**catch-all}` → `file-server` — **public**
- `/api/admin/content/*`, `/api/admin/booking/*`, `/api/admin/identity/*`, `/api/admin/files/*` → guarded by `AdminPolicy`

> ⚠️ The admin guard only covers the `/api/admin/*` prefix; the public catch-alls reach the same controllers unguarded. See [FLOW_INTEGRITY_AND_QA.md](FLOW_INTEGRITY_AND_QA.md) §Authorization.

## 3. Per-service layer breakdown (Clean Architecture)

Each business service (Identity, Content, Booking) uses **API / Application / Domain / Infrastructure** with MediatR CQRS.

### Identity Service
| Layer | Key files | Responsibility |
|---|---|---|
| API | `AuthController.cs`, `UsersController.cs` | register, login, OTP, social login, `/me`, user/role admin |
| Application | `Authentication\Commands\*`, `Roles\Queries\*` | MediatR handlers, FluentValidation |
| Domain | `User.cs`, `Role.cs`, `Permission.cs`, `RolePermission.cs` | Identity profile, roles, permission rows |
| Infrastructure | `DependencyInjection.cs`, `Authentication\JwtTokenGenerator.cs`, `Persistence\IdentitySeeder.cs` | ASP.NET Identity EF store, JWT, seeding |

### Content Service
| Layer | Key files | Responsibility |
|---|---|---|
| API | `ToursController.cs`, `CategoriesController.cs`, `DestinationsController.cs`, `LanguagesController.cs`, `CurrenciesController.cs`, `NationalitiesController.cs`, `Admin\*`, `ConciergeController.cs` | public + admin endpoints |
| Application | `Tours\Commands`, `Tours\Queries`, `Concierge`, `DTOs` | CQRS handlers, tour search/detail, concierge intent |
| Domain | `Tour.cs`, `Category.cs`, `Destination.cs`, `Language.cs`, `Currency.cs`, `Nationality.cs`, `Supplier.cs` | catalog model, localized JSON dictionaries |
| Infrastructure | `ContentDbContext.cs`, `ContentSeeder.cs` | EF Core, PostgreSQL JSONB, seeding |

### Booking Service
| Layer | Key files | Responsibility |
|---|---|---|
| API | `BookingsController.cs`, `FeedbacksController.cs`, `InquiriesController.cs`, `ReportsController.cs`, `NotificationsController.cs` | booking/feedback/inquiry/report endpoints |
| Application | `Bookings\Commands`, `Bookings\Queries`, `Feedbacks`, `Inquiries`, `DTOs` | booking creation, payment/status updates, availability count, feedback |
| Domain | `Booking.cs`, `GuestDetail.cs`, `BookingAddonSnapshot.cs`, `Enums\BookingStatus.cs`, `Services\CancellationPolicyService.cs` | booking aggregate, guest manifest, add-on snapshots, cancellation policy |
| Infrastructure | `BookingDbContext.cs`, `BackgroundServices\CashReservationCleanupWorker.cs`, `Services\TwilioWhatsAppService.cs`, `Email\SmtpEmailSender.cs` | EF Core/PostgreSQL, hourly cash-cleanup worker, WhatsApp/email |

### File Server
Single API project; `FilesController.cs` over `Seadora.Common.Storage.IStorageService` (local). Whitelist: `.jpg .jpeg .png .webp .svg .pdf .xlsx .xls .csv`; max **15 MB**; stored as `{Guid}{ext}`.

## 4. Shared library — `Seadora.Common`
`src\Services\Common\Seadora.Common`:
- `Behaviors\ValidationBehavior.cs` — MediatR + FluentValidation pipeline
- `Middlewares\ExceptionHandlingMiddleware.cs` — problem-json error shaping
- `Logging\CorrelationIdMiddleware.cs` — `X-Correlation-ID` + Serilog context
- `Storage\IStorageService.cs`, `LocalStorageService.cs`, `RemoteStorageService.cs`, `StorageDependencyInjection.cs` — storage abstraction (local vs remote via `StorageSettings:Type`)

## 5. Cross-service communication
- Primary path: **SPA → Gateway → controller → MediatR handler → EF Core → PostgreSQL**.
- **No message bus / gRPC / events.** Purely synchronous HTTP.
- Booking stores a denormalized `TourId` only and does **not** validate it against Content at booking time.
- `Booking.ReportsController` makes synchronous HTTP calls to Content (`http://content-service:8080/api/tours`).
- Content `ConciergeService` calls Booking availability via injected `HttpClient`.

## 7. Frontends
| Aspect | seadora-website (public) | seadora-admin |
|---|---|---|
| Stack | Vue 3.5, Vite, TypeScript, Tailwind, Pinia, Vue Router, Vue I18n | same stack |
| Structure | feature-based (`features/`, `shared/`, `core/`) + some legacy `views/`/`components/` | feature-based with role-guarded router (~25 routes) |
| Auth | WhatsApp OTP + social + email/password (modal, partly unwired) | email/password (page), role whitelist |
| i18n | backend-driven translations + bundled JSON fallback (EN/DE/IT/FR/RU) | mostly hardcoded English |
| API base | `VITE_API_URL=http://localhost:8000` (gateway) | same |

> Note: both frontends contain **duplicate component implementations** (e.g. two `TourDetailsView.vue`, two `Trips.vue`, two `PdfPreviewModal.vue`) — a maintenance/consistency risk. See [FLOW_INTEGRITY_AND_QA.md](FLOW_INTEGRITY_AND_QA.md).
